## Integration recommendations

1. First investigate Pier and Studio 620 public subscription links. Their list layouts resemble calendar exports, but direct candidate ICS retrieval was unsuccessful in the research tool, so neither is verified as a working feed. AMRoC exposes a calendar iframe but underlying feed and permission were not verified. Do not guess endpoints or mark verified based on a plugin pattern.
2. Prioritize New World, Bayboro, Mezzo, Indie Flea and Daddy Kool for incremental coverage. New World directly combines music and a recurring Melee tournament, unusually strong topic fit. Seasonal markets and record store events fit curated review better than speculative scraping.
3. Preserve existing ICS-only ingestion until a permitted new source has been tested. For each source inspect terms, robots guidance, explicit subscription/API documentation, redistribution scope, fees and rate limits. Public access and robots allowance alone are not redistribution permission. If unclear, obtain publisher permission or keep as a manual link. No images or copyrighted descriptions copied.
4. For permitted feeds test unauthenticated GET from deployment environment, response content/type, VCALENDAR parse, stable UIDs, Eastern time conversion, exceptions/cancellations, recurring/multi-day events, duplicate sources and stale fallback; document evidence and sample fixture before enabling. Respect conditional requests and rate limits. Never infer free admission from parking or a generic event description.
5. For manual discovery, propose a reviewed JSON input separate from generated feed output, only if engineering agrees schema/validation and owner approves. Store factual title, exact occurrence, venue, official URL, price status, source and checked date; expire stale entries; no unreviewed publishing. Existing recurring community directory can host stable activities after checking duplicates. Secondary guides are leads, not canonical sources.
6. Keep St Petersburg/Gulfport first, Tampa as expanded radius, Plant City optional outer region. No precise personal location in source data. Venue-level geocoding and travel feasibility are separate PP-003/004 work.
